# 在 autoDL（Linux GPU 服务器）上配置会遇到什么问题

autoDL 是 **Linux + 通常预装 PyTorch / CUDA / ffmpeg 的 GPU 镜像**。本机（Windows + CPU）踩的 4 个坑，在 autoDL 上命运不同：

| 本机遇到的问题 | 是否 Windows 特有 | 在 autoDL 上的命运 |
|---|---|---|
| ① 缺 `trainer` 模块（ModuleNotFoundError） | 否（只是漏装依赖） | 若用官方安装方式 `pip install -e .` / `pip install TTS`，依赖会自动装全，一般不会有；装完建议 `pip show trainer` 确认一下 |
| ② `transformers` 5.x 不兼容 `BeamSearchScorer` | 否（纯版本问题） | **仍可能触发**——只要环境里 transformers 是 5.x，Linux 照样报 ImportError。务必显式锁定 `transformers<5`（如 `pip install "transformers==4.44.2"`） |
| ③ `torch.load` 的 `weights_only=True` 拒绝反序列化 | 否（纯 torch 版本问题，≥2.6 才有） | **仍可能触发**——autoDL 镜像若带 torch≥2.6，Linux 上同样报 `UnpicklingError`。需保留本项目 `TTS/utils/io.py` 的 `weights_only=False` 补丁，或把 torch 降到 <2.6 |
| ④ `torchaudio`→`torchcodec`→ffmpeg **DLL** 缺失 | **是**（DLL 是 Windows 概念） | 基本消失——Linux 上 ffmpeg 通常已预装，torchaudio 直接加载 `.so` 共享库，不会缺 DLL。`xtts.py` 里用 `soundfile` 替换 `torchaudio.load` 的补丁在 Linux 上通常不需要，但保留也无害（soundfile 跨平台） |

## 结论

不是"换到 Linux 就全没了"：
- **④（ffmpeg DLL）** 是真正 Windows 特有的，autoDL 上基本自愈；
- **①** 看安装方式（官方完整安装可避免）；
- **②③** 取决于 torch / transformers 版本，在 Linux 上一样会中招，需要版本锁定或补丁。

## autoDL 推荐配置流程（GPU 推理 / 微调）

1. **选镜像**：优先 PyTorch 官方镜像（已带 torch + CUDA + ffmpeg），避免再单独装 ffmpeg。若镜像里没有 ffmpeg，再补：
   ```bash
   apt-get update && apt-get install -y ffmpeg
   # 或 conda 环境内：conda install -y -c conda-forge ffmpeg
   ```
2. **装依赖（关键：锁版本）**：
   ```bash
   cd /root/Coqui.ai-TTS            # 把项目传上去或 git clone
   pip install -e .                  # 完整安装，自动拉齐 trainer/coqpit 等
   pip install "transformers==4.44.2"   # 显式锁 <5，避免 5.x 的 BeamSearchScorer 报错
   ```
   - 若镜像自带 torch ≥ 2.6，本项目 `TTS/utils/io.py` 的 `weights_only=False` 补丁**必须保留**（否则 XTTS 模型加载报 UnpicklingError）。
   - 想彻底规避 ③，也可改为 `pip install "torch<2.6" "torchaudio<2.6"`，但会失去新版特性，按需选择。
3. **改运行设备**：把脚本里的 `device = "cpu"` 改成 `device = "cuda"`，其余不变（XTTS 在 GPU 上合成快几十倍）。
4. **模型下载位置与加速**：
   - 设置 `TTS_HOME` 指向数据盘或项目目录（autoDL 的 `/root` 或挂载盘），注意 `/tmp` 多为 tmpfs，空间有限，1.8GB 的 XTTS 模型别下到 /tmp。
   - 国内拉 HuggingFace 慢，设置镜像：

5. **运行**：
   ```bash
   python scripts/inference_clone.py
   ```
   首次会下载 XTTS v2 基底模型（约 1.8GB），之后复用本地缓存。

> 提示：本机我们是"把项目根目录加入 PYTHONPATH、不装 TTS 本体"的方式跑（避开 Cython 编译）。在 autoDL 上可以更规范地用 `pip install -e .` 安装；只要依赖装全、版本锁好，两种方式都能跑通。

# 在 autoDL 上搭建 GPT-SoVITS（整合包路线）

> 与 Coqui XTTS 不同，GPT-SoVITS 走"整合包"路线（代码 + 预训练权重打包成 7z），依赖已被作者锁好，省去 Coqui 那堆版本地狱。
> 模型包来源：ModelScope `FlowerCry/gpt-sovits-7z-pacakges`，文件 `GPT-SoVITS-v2pro-20250604-nvidia50.7z`（约 8.84GB）。

## 0. 建 conda 环境与 Python 版本（推荐 Python 3.10）

```bash
conda create -n tts python=3.11 -y
conda activate tts
```

- **选 3.10（3.11 也可，避开 3.12 / 3.13）**：GPT-SoVITS 生态多数依赖在 3.10 轮子最全；且 `nvidia50` 整合包里的预编译 torch 通常按 `cp310/cp311` 编译，Python 版本对不上会导致 wheel 不匹配、被迫现场编译或报错。
- **CUDA 13 驱动 ≠ 问题**：autoDL 实例看到的 CUDA 多为驱动版本，整合包内 torch 按 CUDA 12.x 编译，新驱动向后兼容旧 CUDA 二进制（Blackwell 也能跑），无需强行对齐。
- 解压后优先看整合包自带的 `requirements.txt` / `env.yaml`，按其写明版本对齐最稳。

## 1. 下载与解压（直接在 autoDL 上做，别下到 Windows 再上传）

> **重要经验（实测）**：路线选"直接在 autoDL 下"是对的（别先下到 Windows 再上传，本地上行慢、浪费流量）。
> 但 **`modelscope` CLI 默认单连接下载，会被 ModelScope 存储限速到 ~1 MB/s**（8.84GB 实测 ETA 约 3 小时，并非"几分钟"）。
> **提速做法：改用 `aria2c` 多连接并发下载**，通常能跑满带宽，几分钟到十几分钟搞定。

```bash
# 进数据盘（别放系统盘 /root，空间小且可能随镜像重置）
cd /root/autodl-tmp

# —— 方法 A（推荐）：aria2c 多连接，速度最快 ——
apt-get update && apt-get install -y aria2
aria2c -x 16 -s 16 -d ./ -o GPT-SoVITS-v2pro-20250604-nvidia50.7z \
"https://modelscope.cn/models/FlowerCry/gpt-sovits-7z-pacakges/resolve/master/GPT-SoVITS-v2pro-20250604-nvidia50.7z"

# —— 方法 B：modelscope CLI（慢，单连接，仅作兜底） ——
# pip install modelscope
# modelscope download --model FlowerCry/gpt-sovits-7z-pacakges \
#   GPT-SoVITS-v2pro-20250604-nvidia50.7z --local_dir ./

# 解压（autoDL 的 Ubuntu 常没装 7z，先装）
apt-get install -y p7zip-full
7z x GPT-SoVITS-v2pro-20250604-nvidia50.7z -o./GPT-SoVITS-v2pro
```

> 注：若 aria2 也只到几 MB/s，可能是 autoDL 出口被限，可错峰或换镜像；正常情况下 16 连接能绕开单连接限速。

- **`nvidia50` 对驱动/CUDA 有要求**：该包名指向 CUDA 12.x / RTX 50 系（Blackwell，驱动 50.x）的预编译环境。租实例时**优先选较新 GPU（如 RTX 5090）或较新 PyTorch 镜像**；若选 RTX 4090（驱动约 550）等旧卡，预编译 torch 可能报驱动不兼容——此时换更新的镜像/卡，或改用同仓库不带 `nvidia50` 的普通包。
- 解压后按该整合包自带 README 启动 WebUI / 训练。

## 2. WebUI 能映射到本地机器用吗？（能）

**能。** GPT-SoVITS 的 WebUI 本质是一个跑在 autoDL 实例上的**网页服务**（默认监听某个端口，如 9874）。计算在云端 GPU，页面渲染在你本地浏览器——你在本机浏览器里点的每个按钮，请求都发到 autoDL，结果（音频）再传回本地播放/下载。

autoDL 提供两种映射方式：

### 方式 A：autoDL「自定义服务」（最省事，推荐）
1. 启动 WebUI 时确保服务监听 `0.0.0.0`（不是 `127.0.0.1`），例如：
   ```bash
   python webui.py --host 0.0.0.0 --port 9874
   ```
2. 在 autoDL 控制台「我的实例 → 自定义服务 / 端口」里，把 `9874` 这个端口加进去。
3. autoDL 会生成一个公网代理 URL（形如 `https://xxxxx.gpu-blade.com`），**在本机浏览器打开这个 URL 即可用 WebUI**，无需任何本地配置。

> 注意：自定义服务对暴露的端口有安全提示（相当于公网可访问），不用时记得停掉服务或关闭端口。

### 方式 B：SSH 端口转发（更私密）
若不想走公网代理，可用 autoDL 的 SSH 配置做本地转发（把本地某端口隧道到实例端口），本机访问 `http://127.0.0.1:本地端口` 即可。适合对安全敏感的场景。
